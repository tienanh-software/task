# FlowTask

Full-stack task management starter: React + Vite + Tailwind CSS + Express + MongoDB.

## Features
- Task CRUD, search, status/priority filters
- Dashboard summaries and weekly completion chart
- Kanban board (drag cards between columns)
- Due-soon and overdue indicators
- In-app reminders, generated by a server-side scheduled job
- Responsive light UI

## Run the whole project with Docker Compose (recommended)

Requirements: Docker Desktop (Windows/macOS) or Docker Engine + Docker Compose plugin (Linux).

From the project root (the folder containing `docker-compose.yml`), run:

```bash
docker compose up -d --build
```

Then open **http://localhost:8080**.

Compose starts three services:
- `frontend`: builds the React app and serves it with Nginx on port `8080`.
- `backend`: runs the Express API inside the Docker network on port `5000`.
- `mongodb`: runs MongoDB 7. The backend connects to it using `mongodb://mongodb:27017/flowtask`.

The frontend sends API requests to `/api`; Nginx forwards those requests to the backend container. This means the browser does not need to know the backend container's internal hostname.

### Useful Docker commands

```bash
# See running containers
docker compose ps

# Follow logs from all services
docker compose logs -f

# Follow only backend logs
docker compose logs -f backend

# Restart the stack
docker compose restart

# Stop and remove containers/network (database data is kept)
docker compose down

# Rebuild after changing source code
docker compose up -d --build
```

### MongoDB data persistence

MongoDB data is stored in the named Docker volume `flowtask-mongodb-data`. Running `docker compose down` does **not** delete this volume, so tasks remain after restarting the containers.

To permanently delete the database data as well, run:

```bash
docker compose down -v
```

Warning: `down -v` deletes the MongoDB volume and all data stored in it.

## Deploy to a VPS

1. Install Docker Engine and the Docker Compose plugin on the VPS.
2. Upload/clone this project onto the VPS.
3. From the project root, run `docker compose up -d --build`.
4. Allow inbound traffic to port `8080`, then test `http://YOUR_SERVER_IP:8080`.
5. For a real domain and HTTPS, configure the VPS host Nginx/Caddy as a reverse proxy to `http://127.0.0.1:8080` and enable TLS. Do not expose MongoDB's port `27017` publicly.

For a production VPS, consider changing the frontend port mapping in `docker-compose.yml` from `8080:80` to `127.0.0.1:8080:80` when a host-level reverse proxy is used. This keeps the app port private to the VPS.

## Run without Docker (development)

Requirements: Node.js 20+ and a local MongoDB service or MongoDB Atlas.

Open two terminals.

### 1. Backend

```powershell
cd flowtask\server
Copy-Item .env.example .env
npm install
npm run dev
```

Edit `server/.env` and set `MONGODB_URI` if using Atlas. The API starts at http://localhost:5000.

### 2. Frontend

```powershell
cd flowtask\client
Copy-Item .env.example .env
npm install
npm run dev
```

Open http://localhost:5173.

## Notes

This is an MVP foundation, not a production-hardened multi-user SaaS yet. Authentication, team permissions, email/push delivery, audit logs, backups, and deployment secrets should be added before public production use.
